# QUAY: Qualified Usage, Access and Yield

A DCAT Profile for Data Access, Storage and Authorization Metadata.

**Prefix:** `quay:`
**Namespace:** `https://w3id.org/quay/`
**Ontology IRI:** `https://w3id.org/quay/quay.owl`

## Overview

QUAY extends [DCAT](https://www.w3.org/TR/vocab-dcat-3/) with three pillars for describing how data is accessed, stored, and governed:

- **Usage (U)** — bridges to [ODRL](https://www.w3.org/TR/odrl-model/) for access policies and authorization
- **Access (A)** — `AccessDescription` captures protocol, authentication scheme, and supported operations
- **Yield (Y)** — `YieldDescription` captures delivery mode, temporal quality, coverage, service quality, and verification method

QUAY imports DCAT, Dublin Core Terms, and ODRL. It provides 71 OWL entities (classes, object properties, datatype properties) with ISO 704 Aristotelian genus-differentia definitions.

## SHACL Validation

QUAY includes SHACL shapes ([src/shacl/quay-shapes.ttl](src/shacl/quay-shapes.ttl)) that validate ABox data against structural constraints:

- `DistributionShape` — requires ≥1 access description + ≥1 yield description
- `AccessDescriptionShape` — exactly 1 protocol, ≥1 auth scheme, ≥1 operation
- `YieldDescriptionShape` — exactly 1 delivery mode, ≤1 each for temporal quality, coverage, service quality, verification method

Run validation against all patterns:

```bash
cd src/ontology
bash run.sh make validate-patterns
```
